# ЭДО Договоров — Хранилище документов и согласование

Простая система: договоры, хранилище прикреплённых файлов, согласование по
фиксированному маршруту.

## Маршрут согласования

```
Инициатор создаёт договор
         │
         ▼
     Директор рассматривает
         │
    ┌────┴─────┐
    │           │
"Стандартный"  "Отправить Юристу и Бухгалтеру"
    │           │
  ФИНАЛ          ▼
(Согласован)   Юрист согласовывает
                  │
                  ▼
              Бухгалтер согласовывает
                  │
                  ▼
              Директор — финальная подпись
                  │
                  ▼
                ФИНАЛ (Согласован)
```

Отклонить договор может любой согласующий на своём активном этапе — договор
сразу переходит в статус "Отклонено", дальше маршрут не идёт.

## Роли

`Админ`, `Инициатор`, `Директор`, `Юрист`, `Бухгалтер`.

- Договор может создать любой пользователь.
- Только `Директор` (и `Админ`) видит раздел "Администрирование" (пользователи, юрлица).
- Удалить договор может только его инициатор, и только пока по нему ещё нет
  ни одного решения согласования.

## 1. База данных (Supabase или Railway Postgres)

Выполните **весь** файл `backend/migrations/001_init.sql` в SQL-редакторе
вашей БД (Supabase SQL Editor, или Railway → Postgres → Console → `psql`).

Если у вас уже развёрнута БД с прошлой (более сложной) версией системы —
выполните вместо этого `backend/migrations/005_reset_to_contract_only.sql`,
он сам сносит старые таблицы и пересобирает всё заново.

⚠️ Оба варианта создают тестового администратора `admin@example.com` /
`admin123` — смените пароль сразу после первого входа.

## 2. Backend (Railway)

Переменные окружения (Variables сервиса):
- `DATABASE_URL` — строка подключения к Postgres
- `JWT_SECRET` — случайная строка
- `CORS_ORIGINS` — домен фронтенда (или `*` на время отладки)
- `UPLOAD_DIR` — папка для загруженных файлов, **обязательно** на смонтированном
  Volume (например `/data/uploads`), иначе файлы пропадут при следующем деплое
- `MAX_UPLOAD_MB` — необязательно, лимит размера файла (по умолчанию 20)

Локальный запуск:
```bash
cd backend
python3 -m venv venv && source venv/bin/activate
pip install -r requirements.txt
cp .env.example .env   # впишите DATABASE_URL и JWT_SECRET
uvicorn app.main:app --reload
```

## 3. Frontend (Railway)

Переменная окружения: `VITE_API_URL` — адрес backend.

```bash
cd frontend
npm install
cp .env.example .env.local   # укажите VITE_API_URL
npm run dev
```

## Тесты

```bash
cd backend
python3 contract_flow_test.py
```
Проверяет весь маршрут: создание, решение Директора (стандартный/нет),
последовательность Юрист→Бухгалтер→Директор, отклонение на любом этапе,
удаление, загрузку файлов и их привязку к договору в хранилище документов,
дашборд, экспорт в Excel, список ролей.

## Хранилище документов

Файлы (договоры, сканы и т.п.) загружаются кнопкой "📎 Прикрепить файл" —
хранятся физически на диске backend-сервиса (не просто ссылка). Каждый
загруженный файл сразу попадает в общий реестр — раздел **"Хранилище
документов"** в меню — с поиском по имени файла, названию договора и тому,
кто загрузил. При создании договора файл автоматически привязывается к нему
в этом реестре.
